# Contributing to AetherOS

## Branching
- Create focused feature branches.
- Keep changes scoped to one subsystem when possible.

## Development Flow
1. Select the target module directory.
2. Implement feature changes with tests.
3. Run relevant lint and test commands.
4. Open a pull request with architecture impact notes.

## Quality Expectations
- Preserve modular boundaries.
- Avoid hard-coding platform assumptions.
- Prefer shared contracts in `shared/`.
